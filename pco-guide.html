港口掛靠優化
（Port Call Optimization）指南

由 IAPH × IHMA 聯合發布，統一航海與營運資料的電子交換標準，推動全球港口安全、永續與高效運作。

版本：Concept V1 有效期：2026.04.01 — 2031.04.01 提交單位：IMO FAL 50 保管機構：IHMA
Section 01
什麼是港口掛靠優化（PCO）？
核心定義：港口掛靠（Port Call）是船舶在航行途中抵達並離開特定港口的過程，期間可能停靠一個或多個泊位。PCO 即是優化此全流程的系統性方法。
⚓

安全性提升

標準化、精確且即時的資訊，能提升港口掛靠的安全性與法規合規程度。

🌿

環境永續

準時到港（JIT）大幅降低船舶在錨地等待時間，減少燃料消耗與溫室氣體排放。

⚙️

營運效率

港口、航商、貨主及碼頭共享一致資料，優化人力、設備與資源調配。

💰

降低成本

減少船舶閒置、泊位空等及相關服務延誤，降低全供應鏈的整體運營成本。

Section 02

IMO FAL 50 — 正式提交 PCO 指南；國際 API 測試台（IHO 托管於 GitHub）啟動，開放港口接入，有效期至 2031 年。

Section 04
航海資料 — 最小資料範疇
原則：「基礎與合規優先（Basics and Compliance First）」 — 與 SOLAS 船舶設備最低配備要求同理，港口也需提供最小資料集。
🏭

碼頭（Terminal）

必要欄位：唯一識別碼（GLN）、名稱、地理座標（WGS84）、碼頭類型。

散貨 貨櫃 渡輪 油輪 Ro-Ro 旅客
⛽

泊位（Berth）

必要欄位：唯一識別碼（GLN）、名稱、地理座標（防舷材線 A–B 兩端）、泊位類型。

碼頭 Quay 棧橋 Jetty 浮筒 MBM 錨泊
為何使用 GLN（全球位置號碼）？
GLN 是 ISO/IEC 6523 標準，已在全球供應鏈中使用逾 30 年，具備與 IHO 互通識別碼（Interoperability Identifier）及 ISO 19987 的相容性。與船舶 IMO 號碼配合，可確保穩健的「船－泊相容性」（Ship-Berth Compatibility）查核，避免因名稱更名或拼寫差異而造成資料不一致。

兩個最關鍵的時間戳記：
① 計劃抵達引水員登船點時間（PTA PBP）—讓船舶可提前優化航速，避免在錨地等待。
② 計劃離泊時間（PTD Berth）—讓船舶、航商、服務商均能提前規劃，降低閒置時間。

Section 06
主要效益

🚢 航運公司 / 租船人

  • 早期獲得 PTA 引水員登船點，可提前優化航速及氣象航線規劃
  • 減少在錨地漂泊或高速衝刺後等待（SFTW 現象）
  • 降低燃油及潤滑油消耗，減少船體污損與被盜風險
  • 提前知悉 PTD，可不脫班安排保養、燃補或換班

🏗️ 碼頭 / 泊位規劃者

  • 更佳的泊位容量規劃
  • 更精準的設備與人力資源調配
  • 統一的國際時間戳記定義，減少溝通誤差

⚓ 港口規劃者

  • 優化港內航道使用，提升容量規劃精度
  • 降低碰撞風險，提升整體安全性
  • 減少港區內的廢氣排放

🗺️ 水文機構

  • 透過 API 自動取得最新碼頭/泊位資料，大幅縮短 ENC 更新週期
  • 首次實施結果顯示：約 50% 碼頭的類型或名稱原本有誤
Section 07
如何加入 PCO 全球港口網路
1
建立或整理資料來源 — 確認碼頭與泊位資料（可來自 GIS 資料庫、客戶資料庫或 Excel 試算表）
2
對應國際標準欄位 — 依 IHO 概念登錄及 IMO 彙編，調整本地資料模型
3
向 GS1 申請 GLN — 取得碼頭與泊位的全球唯一位置號碼
4
建立符合標準的 API — 採用 JSON 格式、ISO 8601 時間、WGS84 座標，認證方式可用 API Subscription Key（航海資料）或 OAuth 2.0（營運資料）
5
提交 API 至 IHO GitHub 測試台 — 通過測試後，正式列為 PCO 網路港口（PCO Network Port）
6
全球資料使用者接入 — 租船人、船舶運營商、港口資料庫均可透過同一 API 即時取得資料

Section 08
關鍵重點一覽

📌 最小航海資料

碼頭與泊位的唯一識別（GLN）、名稱、座標、類型，僅限接待 SOLAS 船舶者須提供。

📌 最小營運資料

PTA 引水員登船點 與 PTD 泊位 是對外 API 公開的兩個核心時間戳記。

📌 標準堆疊

GLN（ISO/IEC 6523）＋ WGS84 ＋ ISO 8601 ＋ UN/LOCODE ＋ IMO 船舶號碼，構成完整標準體系。

📌 資料所有權

航海資料由港務長等公權力機關持有；營運資料由港口規劃者持有，泊位規劃者（碼頭）提供輸入。

📌 建議實施順序

先從靜態的航海資料著手，再推進到動態的營運資料，循序漸進降低風險。

📌 法律框架

資料共享可透過國家港口法令、盟約（Covenant）、港口規則或租地合約等多種方式正式化。
